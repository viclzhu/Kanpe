# Working on Kanpe

Kanpe is a SwiftPM macOS app (macOS 13+, Swift tools 5.10). It is built with the Command Line Tools only, with no Xcode project. Read `README.md` for user-facing behaviour. This skill covers what the README doesn't: how to work on the code and what has gone wrong before.

## Map

| Path | What it holds |
|---|---|
| `Sources/KanpeCore/` | Pure logic with no AppKit. Put new logic here so the self-tests can cover it. |
| `SitePacks.swift` | `DetailLevel`, `SitePack` (with `Page`, `Group` and `Entry`), `SiteMatcher` (host and path-prefix matching), `PathPattern` (`*`, `**`, globs, `{a,b}`, `!`), and `SitePackStore` (install, load, save, revert, and the `.installed.json` manifest). |
| `Editing.swift` | `EditableSite`, the editor's copy of a pack. Groups, shortcuts and pages carry UUIDs, and groups link to pages by ID, so renaming a page keeps its links. Also `KeyRecording`. |
| `Models.swift` | `Shortcut`, `ShortcutGroup` (with `part`, used by column splitting), `PanelContent` and `SiteInfo`. `SiteInfo` holds the level, the current pages and `pageFiltering`. |
| `KeyNotation.swift` | Pack `keys` notation to glyphs. Spaces separate a sequence, `+` joins a chord and ` or ` separates alternatives. Also handles menu modifier masks; bit 8 means no ⌘, which gives an "fn " prefix for bare letters. |
| `Layout.swift` | Newspaper columns. `ColumnLayout.best` scores each column count by shape (closeness to the screen's aspect, weighted by how much of the screen the panel covers) plus `wasteWeight` × blank area (ragged column ends, strip under a wide header). Columns widen up to `Metrics.maxStretch` to fill the header, and the same `columnWidth(for:)` is used for scoring and drawing. Groups of 10 rows or more (`minSplitRows`) may split; each piece has at least 3 rows (`minChunk`). |
| `Trigger.swift` | `TriggerStateMachine`, a pure state machine for the hold and double-tap-hold gestures. |
| `Sources/Kanpe/` | The AppKit/SwiftUI app. |
| `AppDelegate.swift` | Main hub (`@MainActor`). Prefetches on gesture start, `render()` builds `PanelContent`, and builds the status menu. Per-site and per-app settings live in UserDefaults dictionaries: `siteLevels`, `sitePageFiltering`, `appMenusVisible`. |
| `ActivationMonitor.swift` | Global and local NSEvent monitors that feed `TriggerStateMachine`. |
| `MenuReader.swift`, `BrowserURLReader.swift`, `AX.swift` | Accessibility reading. Chromium browsers need `AXManualAccessibility = true` before their `AXWebArea`/`AXURL` appear; AppleScript is the fallback. |
| `PanelController.swift`, `PanelView.swift` | Non-activating floating panel. `PanelHeader` is its own view because the layout measures its width. |
| `Editor/` | SwiftUI `NavigationSplitView` editor. Autosaves with a 0.5 s debounce. `KeyRecorder` uses a local keyDown monitor. |
| `main.swift` | Debug CLI modes (see Verify below), then app start inside `MainActor.assumeIsolated`. |
| `Sources/KanpeSelfTest/main.swift` | Assertion checks. Run them after every change. |
| `Resources/Sites/*.json` | Bundled site packs (GitHub, Gmail, YouTube). |
| `Resources/AppIcon.icns` | App icon, generated by `scripts/make-icon.swift`. |
| `scripts/bundle.sh` | Builds and signs `build/Kanpe.app`. |
| `scripts/setup-signing.sh` | One-time setup of the stable signing identity. |

## Build and test

```sh
cd /Users/victor/Workspaces/Kanpe
swift build && .build/debug/KanpeSelfTest   # must end with "All checks passed"
pkill -x Kanpe; scripts/bundle.sh && open build/Kanpe.app
```

- **No test frameworks:** XCTest and swift-testing are not available with the Command Line Tools. Add checks to `KanpeSelfTest` with `check(actual, expected, "label")`. It also loads the bundled packs from `Resources/Sites` and checks them: no empty chords, levels that grow, and GitHub page matches.
- **Fast builds:** an incremental `swift build` often takes 1–2 s. If you doubt that it picked up a change, compare timestamps (`ls -lT .build/debug/KanpeSelfTest Sources/...`) or `strings` the binary for a new string.
- **Stale build state:** if SwiftPM reports odd "build description" errors, run `rm -rf .build`.
- **Quit before rebuilding:** run `pkill -x Kanpe` before `bundle.sh`, then `open build/Kanpe.app` to relaunch.

## Accessibility permission (the #1 source of "trigger doesn't work")

- **Why grants break:** macOS ties the Accessibility grant to the code signature. Ad-hoc builds get a new identity on every build, so a grant goes stale. It still shows as on in System Settings but does nothing, and toggling it doesn't help.
- **Stable signing:** `bundle.sh` signs with the self-signed identity "Kanpe Local Signing" from `scripts/setup-signing.sh`, so grants survive rebuilds. Keep it that way.
- **Bundle ID:** `dev.victorzhu.Kanpe`. Changing it, or the signing identity, means the user has to grant permission again.
- **Fixing a stale grant:** run `tccutil reset Accessibility dev.victorzhu.Kanpe`, relaunch, and grant again. The menu has the same action as **Reset Permission and Ask Again**.
- **Checking trust:** the launch log says `accessibility trusted: true/false`.

## Verify changes in the real app

- **Logs:** `/usr/bin/log stream --predicate 'subsystem == "dev.victorzhu.Kanpe"' --level debug`. The categories are `trigger` and `app`. Use the full path, because in zsh `log` is a builtin. For recent history: `/usr/bin/log show --last 2m --predicate '…' --style compact`.
- **Panel render:** `build/Kanpe.app/Contents/MacOS/Kanpe --render com.google.Chrome /tmp/out.png <url> [--level core|extended|complete] [--hide-menus] [--all-pages]` renders the panel to a PNG. The URL overrides the real tab. Read the PNG to check it.
- **Layout changes:** render a fixed set before and after, and compare sizes and gaps. Cover small cases (an issue page or the home page at Core, with `--hide-menus`), a PR page at Extended and Complete, `--all-pages --level complete`, a page with menus shown, and a non-browser app such as `com.apple.finder`. Big cases should keep their size unless that's the point of the change.
- **Text dump:** `--dump <bundle-id>` prints what the panel would show.
- **Editor render:** `--render-editor /tmp/editor.png [SiteName]` renders the editor. It needs Screen Recording for the terminal, uses `CGWindowListCreateImage`, and only shows the top of the window, with no scrolling.
- **Trigger, end to end:** compile `scripts/tap-trigger.swift` from this skill. It posts a synthetic ⌘ tap followed by a hold. Then check the logs for show and hide.
- **Dock state:** `lsappinfo info -only ApplicationType Kanpe` reports `UIElement` when the app is menu-bar only and `Foreground` when it has a Dock icon.
- **Shell tools that don't work here:**
  - `timeout` is not installed.
  - `qlmanage -t` can hang forever, so don't use it to check the icon. Instead, extract the icon with `iconutil -c iconset` and read a PNG from it.

## Site packs: behaviour that bites

- **The user's copies:** the app uses the packs in `~/Library/Application Support/Kanpe/Sites/`. On launch, `installDefaults` copies bundled packs there, but it replaces a file only if the user hasn't edited it. It tracks this with FNV digests in `.installed.json`. Deleted built-in packs stay deleted.
- **Rolling out a bundled change:** after changing a bundled pack, check whether the user's copy will update:

  ```sh
  git show HEAD:Resources/Sites/x.json | cmp - ~/Library/Application\ Support/Kanpe/Sites/x.json
  ```

  If the user has edited it, don't overwrite it silently. Back it up, merge their edits into the new version, and tell them.
- **Formatting differences:** the editor saves through `JSONEncoder`, so formatting alone can differ from the bundled file. Compare parsed JSON to find real edits.
- **Defaults:** shortcuts without a `level` count as Core, and a pack with only one level gets no level picker. A group's `level` applies to its shortcuts, and a shortcut's own `level` overrides it.
- **Pages:**
  - Groups without `pages` show everywhere on the site.
  - With page filtering on (the default, stored per site), page-specific groups show only on their pages and come first.
  - List pages from general to specific, because the header shows the last match.
  - Use `{a,b}` for exclusion lists so the editor shows one chip instead of dozens.
- **Updating `availableLevels` and counts:** for bundled packs, the self-test requires Core < Extended < Complete.

## SwiftUI and Swift gotchas seen here

- **Markdown in `Text`:** `Text("…")` with a string literal is parsed as Markdown, so `*…*` becomes italic and `/*/*/issues` loses its stars. Use `Text(verbatim:)` for paths and patterns.
- **Substring concatenation:** `Substring + Substring` doesn't compile in some contexts. Convert with `String(...)` first.
- **Styled menu labels:** a `Menu` with a custom styled label needs `.menuStyle(.button).buttonStyle(.plain)` to keep its colours, because borderless strips them. Give it a fixed width so rows line up.
- **Chip layout:** `FlowLayout` measures children with an unspecified proposal. For long chips, set `lineLimit(1)`, a max-width frame, `.fixedSize(horizontal:)` only for short text, and put the full text in `.help`.
- **Main-actor isolation:** `AppDelegate` is `@MainActor`, so timer and callback closures need `MainActor.assumeIsolated` or a hop to the main actor.
- **Keyboard shortcuts in the editor:** a hidden main menu (`makeMainMenu`) is what makes ⌘C/V/X/Z/A/W work, because the app is an accessory with no visible menu bar.
- **Dock icon:** the app is `LSUIElement`. The editor turns on a Dock icon (`.regular`) only if **Show Dock Icon While Editing** is on, and switching the activation policy can hide the window, so it's brought to the front again afterwards.

## Repo conventions

- **Commits:** Git author is Victor Long Zhu <victorvctr.zh@gmail.com>, set in this repo's local config. Write one focused commit per feature, with a short summary line and a body explaining why. Push only when asked. The remote is `git@github.com:viclzhu/Kanpe.git` (SSH).
- **README:** when behaviour changes, update `README.md` in the same commit. That includes new pack fields, menu items, panel controls and debug flags.
- **Icon:** to change the app icon, edit `scripts/make-icon.swift`, run `swift scripts/make-icon.swift Resources/AppIcon.icns`, and look at `/tmp/kanpe-icon-preview.png`.
- **Before calling a UI change done:** build, run the self-tests, bundle, relaunch, and render the panel or editor to a PNG and look at it.
